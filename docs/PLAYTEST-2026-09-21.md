# Specialist playtest — 21 September 2026

This round fixes problems found by browser, combat and server-reliability specialists. Implementation stays in the primary repository; Chrome runs in the Browser Testing workspace. Source review: [Farfield PR #1](https://github.com/b00ste/farfield/pull/1).

## Player-facing changes

- Rapid Friend orders keep the latest destination. Escape, menus, disconnects and match end clear unsent actions; an already accepted command remains authoritative.
- Map clicks show pending, accepted or rejected feedback. The HUD explains the Friend’s current task and visible attack target without revealing hidden enemies.
- Guards recalled from follow/hold orders can staff buildings again. Workers evacuating a dismantled building cannot be reassigned until safe, and the Friend cannot be sent back onto its clearing tiles.
- Pursuit stops when a target dies or leaves vision. Automatic combat resumes the interrupted job; explicit attacks end in idle.
- Worker controls fit narrow screens without horizontal drift during vertical swipes.
- Online matches keep running with hidden tabs or open menus. Disconnect expiry works even with no active viewers, and simultaneous expiry ends in a draw. Leaving is separate from backgrounding and preserves the remaining player’s result.

## Transport and recovery

The first fresh seven-minute browser stress run reached 237 buildings and 256 workers, with 493 successful commands and no page/game-command errors. Its complete network report exposed **850 HTTP 429 responses** from sync polling. A shorter reproduction confirmed the proxy’s exact limit: 512 requests per minute. This supersedes earlier reports that did not fully count sync failures.

Room updates now use one authenticated server-sent-event connection per game frame through the trusted host. Commands stay on the existing authenticated API. Presence sync occurs only on menu/visibility changes, with heartbeat detection, bounded retries, cancellation and safe stream replacement. Server views still enforce fog of war. No proxy limit was changed.

Optional private snapshots save practice rooms every five seconds and on graceful shutdown. The current preview and prepared Docker deployment enable them. Crash recovery can lose changes since the last successful checkpoint; this is single-process recovery, not multi-server failover.
